# Error酱

Error酱 是一个自托管的个人工作与学习站点。最开始它只是想做一个电子元件库存管理系统，后来慢慢长成了一个网站：仓库、书签、笔记、财务、工作台、AI 提示词、留言、动态和推荐，都放在同一个站里。

- 技术栈很朴素：Python 标准库 HTTP 服务 + SQLite + 原生 HTML / CSS / JavaScript，没有前端框架，也没有构建步骤。
- 数据全部保存在自己的机器上（`data/` 目录），不依赖第三方服务。
- 手机浏览器可以直接使用，适合局域网自用，也可以放到云服务器上通过 Nginx 反代公网访问。
- 界面使用 vivo Sans SC 字体，相关说明见文末「字体」一节。

源码仓库：<https://github.com/IslaGiftia/ErrorJ>

## 功能

### 仓库（电子元件库存）

- 元件档案：型号、LCSC 编号、品牌、分类、封装、温度范围、耐压、描述、数据手册链接、最低库存提醒和图片。
- 分类树与存放位置树：默认预置电阻、电容、IC、连接器等分类，以及 `XP`、`XA`、`A~Z` 等位置，可继续扩展层级；分类和位置可以组合筛选。
- 搜索同时支持型号、LCSC 编号、位置路径、位置代码、分类名称和描述。
- 批次库存：按批次记录可用数量、已出库数量、购买日期、单价、渠道、订单号和备注；支持快速入库、快速出库。
- 出入库记录可以修改时间和备注，删除后会自动回补库存；所有删除都有二次确认。
- 项目追溯：出库时可关联项目，随时查看每个项目用了哪些元件、各用了多少。
- 待购入清单：记录想买但还没买的元件，可一键转为采购入库。
- LCSC 导入：支持立创商城导出的 `.xlsx`，自动识别字段，并可在后台按 LCSC 编号批量抓取商品图片。
- BOM 缺料对比：导入 PCB 设计软件导出的 BOM（`.csv` / `.tsv` / `.txt` / `.xlsx` / `.xls`），自动识别位号、型号、封装、数量等字段，按 LCSC 或 MPN 匹配库存，生成缺料清单并导出 CSV。
- BOM 文件夹监控：指定本机目录后，服务会定期扫描新放入的 BOM 文件并自动生成报告；同一文件内容不变时不会重复处理。
- 新建项目时可以直接选择 BOM，保存项目后自动完成对比并把报告关联到项目。
- 分类图标、图片悬停放大、搜索栏吸顶、右下角方形毛玻璃「顶部」按钮（和留言 / 动态同一颗，往下滚才出现）等细节都已处理。

### 网页收藏

- 导航模式和列表模式两种视图，支持文件夹归类和多选批量操作。
- 手动拖动排序，也可以按最近添加、最早添加、标题或文件夹排序。
- 内置失效链接检查，可以只查看失效项并批量清理。
- 每个收藏可以保存说明和备注，图标会缓存到本地。
- 右下角是和留言 / 动态同一颗方形毛玻璃「顶部」按钮（48×58、圆角 10px、浅色深色各自配色）：往下滚才出现，导航视图和列表视图各滚各的，点一下回到当前视图的顶部。
- 推荐模块可以直接引用网页收藏，收藏改名后推荐卡片会自动同步。

### 学习笔记

- Markdown 源文编辑 + 实时预览，支持标题、列表、引用、代码块、表格和链接。
- 顶部固定大纲与面包屑，实时解析 H1/H2/H3，滚动时自动高亮当前小节。
- 图片可以上传、粘贴或拖拽进编辑器，上传前自动缩放到最长边 2000px。
- 笔记列表支持搜索标题、正文和标签，可按标签筛选、按更新时间或标题排序。
- 支持导入 TXT、Markdown、HTML、Word（DOC / DOCX）和 PDF，自动转换为站内 Markdown；Word 内嵌图片会提取到图库，扫描版 PDF 暂不支持 OCR。
- 右下角同样是那颗方形毛玻璃「顶部」按钮：没打开笔记时回到列表顶部，打开笔记后回到正文顶部。
- 粘贴内容会自动做一次初步排版：剪贴板里有 HTML（网页、Word、微信富文本）就先转成 Markdown，浏览器里复制整页会用 Mozilla Readability（Apache-2.0，`static/vendor/readability.js`）剥掉导航 / 广告 / 页脚只留正文，选区内复制则只取所选片段；只有纯文本时走规则排版——统一列表符号、把明显的短行识别成标题、把被硬换行切断的长行接回同一段、中文与英文数字之间补空格（盘古之白）。已经排好的 Markdown、代码块里的内容和过短的内容（一个词、一条链接）都不会被改动。排完可以直接 Ctrl+Z 撤销，顶栏也有「智能排版」按钮可以随时对选中内容或整篇再来一次。
- 单篇笔记可以导出为单文件 HTML：图片以 data URI 内嵌，正文保留 Markdown 源文，可离线打开。
- 手机上看笔记以「看」为主：点开一篇笔记后，顶部的品牌 / 搜索 / 导入 / 新建那一行会自动收起，只留「返回 + 操作」一条细导航条，屏幕基本让给正文；正文上滑时标题、标签和创建 / 更新时间也一起收起，下滑或滚回顶部自动展开。笔记列表上滑同样收起上方功能区（搜索、导入 / 新建、排序和标签），下滑复原；正在搜索框里打字时不会收起。

### 财务

- 独立页面 `/finance`，旧地址 `/aa` 会自动跳转。管理员和获得 `aa:view` 权限的普通账号才能进入；游客访问会被重定向到登录页，未授权账号会被挡回首页，页面和 `/api/aa/*` 接口都在服务端校验权限。
- 首页的「财务」入口只对管理员和获授权账号显示，普通账号默认没有这个权限，需要在「工作台 → 账号权限」里按账号授予。
- 页面功能按钮统一放在右上角横排，使用与足迹工具按钮一致的 40px / 手机 38px 方形尺寸；只有「新建账目」使用主题色。管理员可以维护账目名称和费用备注快捷选项，也能在新建账目、记费用时直接输入自定义内容。
- 每笔费用记录付款人、金额、备注和本笔分摊成员。费用添加人可以自行选择分摊人，系统只在选中的成员之间平均分摊；历史费用会自动回填为当时的全员分摊。
- 「记一笔」位于费用明细标题右侧，点击直接新增本地空白行，不弹窗；填好金额、备注和分摊人后点灰色对号保存。已有费用点击金额、备注或分摊人区域即可整行进入编辑态，点对号保存并恢复文字显示，删除仍是 900ms 长按确认。
- 费用页右侧只保留「转账方案 → 成员结算」；收款码统一从右上角功能按钮打开成员收款码面板。
- 每位成员都能添加、更换和删除自己的收款码，管理员可以代管全部成员的收款码。收款码入口点击后展开成员列表，可同时查看多人的二维码。
- 手机端账目列表默认在进入账目后折叠，标题旁的箭头按钮可随时展开或收起。
- 所有操作按钮接入 Error酱 统一的按压回弹、液态填充、磁吸光晕、加载对勾、成功微粒和长按删除反馈；系统开「减少动效」时按全站规则降级。
- 费用使用整数分保存，避免浮点误差；每笔费用除不尽的 1 分会依次分给该笔分摊成员中排在前面的成员，所有成员净额严格相加为 0。

### 地图

- 首页右下角是「足迹」入口，画面是一张线稿城市地图（浅色主题用黑线那张、深色主题用白线那张），按原画幅 1:1 直接铺在入口里，不裁成圆形，也不再往里塞一张活的 Leaflet 小地图 —— 首页因此不再加载 Leaflet 与地图瓦片，游客也不用再下载静态底图。有地图权限时点开进入 `/map`；游客和无地图权限的账号点了弹一句提示、不跳转。入口下方显示「N 个标记」或「N 条提醒」，有未读时右上角出现角标、入口同时轻微放大缩小提示（约 2.4 秒一次，只缩放、不做光晕），系统开「减少动效」时不缩放、只留角标。入口上方的 PING / FPS 面板贴着画面实际可见的顶边（间距固定 8px，不随入口尺寸变化；线稿图最上面约 8% 是透明的，所以按入口高度 × 0.92 计算）。这块面板连同入口只在首页显示，其它页面都不出现。新增、编辑或删除足迹后，入口的标记数与角标会在返回页面或标签页重新可见时自动刷新；新增足迹也会进入首页左下角公开动态。点入口弹出的提示条（游客是「请登录后操作」，无地图权限的账号是权限说明）以入口中心为参考点居中浮在它正上方，8px 圆角、暗色填充 #20232a，跟站内其它页面的提示条统一。
- 标记支持名称、别名、地址、招牌推荐、标签、备注、经纬度、打卡状态（想去 / 去过）、推荐度（1~5 星）和照片（默认每个标记最多 9 张、单张不超过 8MB，可在工作台「上传限制」调整），按分类着色并用一个字做图标。
- 分类是两级结构：一级分类（例如美食、景点、酒店）下面可以挂二级分类，管理员可以新增、改名、换色换字、删除一级或二级分类；改名时如果图标还是旧名字的首字（自动图标），会自动更新为新名字首字，手动设置的自定义图标会保留，已经标记的地点会跟着分类名字和图标一起更新。历史上留下的占位图标（名字改过、图标还停在「新」）会在服务启动时自动修复一次，导入文件里没带图标的分类直接用分类名首字。删除一级分类时它的下级分类会一并删除，原来的标记会变成未分类。分类管理弹窗里一级分类默认折叠，点每行左侧的箭头展开或收起它的下级分类；新增一级分类或下级分类后会自动滚动到新行并选中名称，可以直接改名。添加 / 编辑标记时，「一级 / 二级分类」在电脑上仍是表单里的原生下拉（位置和交互都不动），手机上改成点一下从底部滑出的分类面板：行样式、圆形色点、选中高亮和电脑端分类筛选面板完全一致，列表长了在面板内滚动；选一级会把二级清空并按新的一级重建二级列表，选完回填到表单并收起面板。
- 管理员可以编辑和管理所有标记；普通账号可以新增标记，并编辑、移动、删除自己新增的标记和照片，不能改动别人的和管理员添加的内容。
- 支持关键字搜索、一级 / 二级分类筛选、标签筛选、聚合显示、定位、全览，以及高德导航链接。
- 按「添加者」筛选：**管理员**点开站内弹窗可以选择任意一位用户，只显示他添加的标记（手机上也用同一套站内弹窗，不再弹浏览器自带的选择器）；**普通账户没有挑人的权限**，这个按钮变成开关，只在「全部标记」和「只看我添加的」之间切换，弹窗根本不会出现。
- 右上角四枚竖排图标是「图层 / 定位 / 全览 / **搜索**」：点「搜索」，输入框从按钮左侧滑出（Slide Left）并自动聚焦，回车或再点一次按钮开始搜；结果面板在输入框下方展开，列出地点名称和详细地址，点外部 / 失焦 / ESC 都会让输入框向右收回。选中一条结果后：搜索框收回 → 地图平滑移到该点 → 直接进入中心选点模式（水滴落在正中央，右侧 ✅ / ❌），点 ✅ 弹出的「添加标记」弹窗会自动带入该地点的名称和地址（高德 GCJ-02 坐标自动换算成 WGS-84），点 ❌ 取消。搜索按钮用主题色填充，风格与操作卡片里的「+ 添加标记」一致（桌面 40px、手机 38px），搜索框与它严格等高对齐。原来写在「添加标记」弹窗顶部的那块搜索 UI 已整体移除，PC 与手机是同一套交互。
- 底图可在右上角切换：高德矢量、高德卫星、Esri 深色、Esri 卫星和 OSM 标准；高德底图会自动做 WGS84 与 GCJ-02 坐标换算，保证标记不偏移。
- 底图按主题分别记忆：浅色模式默认高德矢量、深色模式默认 Esri 深色，在每个主题下手动换过底图后，下次进入该主题仍是你的选择；重新进入站点时会按 Error酱当前的全局主题取对应底图。深色底图额外叠加地名注记，并限制到瓦片原生缩放级别，避免放大后发虚。
- 底图瓦片由访客浏览器直接向高德 / OpenStreetMap / Esri 获取，不经过 Error酱 服务器；服务器只提供页面、标记数据和照片，所以浏览地图不会增加服务器带宽压力。
- 导入仅管理员可用（普通账号看不到导入按钮）：支持 GeoJSON、KML、GPX、CSV（名称,经度,纬度）和 MapBridge 插件导出的高德收藏（`format: mapbridge`）。普通文件可以在导入时选择坐标来源：WGS-84（OSM / Google）、GCJ-02（高德 / 腾讯网页导出）或 BD-09（百度），系统会自动换算成 WGS-84 后再保存；MapBridge 文件的坐标本来就是 WGS-84，会自动识别处理。目标分类留空时按文件里的分类路径自动归类（管理员会创建缺失的分类），选择具体分类则全部归入该分类；同名同坐标的标记会自动跳过，可以放心重复导入。
- 全新安装时地图是空的，不含任何内置示例标记；迁移数据可以用页面上的导入，或用 `tools/map_transfer.py` 在两台机器之间整体迁移（带分类树、打卡状态、评分和照片）。
- 瓦片来自高德、OpenStreetMap、Esri 的在线服务，标记数据始终只保存在自己的 `data/` 里；如果地图内容是私密的，设置 `INVENTORY_MAP_PUBLIC=0` 后地图只对管理员可见。
- 普通账号新增标记时会推送一条「新的标记点」通知（不产生角标），通知里带 `/map?place=<id>` 链接，点开自动定位到该标记并弹出详情。
- 标记点卡片底部是一排三个等宽按钮：「导航 / 编辑 / 删除」。导航固定走高德地图；编辑和删除只对有权限的人出现，三个按钮的尺寸和风格完全一致。原来的「点赞 / 打卡」互动已整体下线（接口、计数、首页提醒和 Webhook 推送一并移除），卡片上不再有点赞、打卡按钮。
- 进页面时**默认只显示左下角的操作卡片**，检索卡片是收起状态（桌面端向下滑出、手机端滑到屏幕外），点「开合检索区」那张卡片才滑出来；这样加载时没有卡片闪动或跳变。
- 手机上的标记清单（搜索区）占满上方整块：展开时右上角的图层 / 定位 / 全览 / 搜索四枚会向右滑出把位置让给它，收起时滑回原位；展开后搜索框和结果列表都完整显示。点底部卡片上的箭头滑出、再点一次收起，也可以直接从卡片顶部往下滑收起。
- 手机端浮层让位联动：点「分类」或「添加者」时，右上角那四枚也按同一套动画向右滑出，浮层可以用满上方空间（不再受「不超过检索卡片高度」以外的限制，所以卡片能完整展开）；浮层一关它们就滑回来。两个浮层与工具列用的是同一条 `0.22s` 缓动，滑动同步。
- 手机上这块区域按紧凑排版：标题行、搜索框都收过字号和留白（412 宽下实测顶部 216 → 111px，首屏可见标记从 10 条增到 16 条）；搜索框下面直接就是标记列表，中间只留 8px 间距。
- 手机上和桌面端是同一套筛选：分类走底部操作卡片最左的「分类」按钮（多级树面板），添加者走它右边的「添加者」按钮，两者的浮层都锚在操作卡片正上方、宽度与检索卡片严格相等，点面板外或按 ESC 关闭。
- 地图上的操作按钮一律是**纯图标**（分类 / 添加者 / 导入标记 / 分类管理 / 开合检索区 / 添加标记 / 图层 / 定位 / 全览），文字说明走悬停提示（桌面端）和 `aria-label`（读屏），按钮不再显示文字标签。
- 手机上的底部是一张常驻的**操作卡片**，和上面的检索卡片分开（中间留 10px），里面是六枚等宽纯图标按钮（分类 / 添加者 / 导入标记 / 分类管理 / 开合检索区 / 添加标记），均分整行、触控高度都是 44px；卡片铺满整行，版权条会自动抬到卡片上方，不会被挡住。手机端点这些按钮不弹任何文字提示，直接执行动作。
- 桌面端左下角是**两张分开的卡片**：上面是检索卡片（搜索框 → 结果列表，收起时整张卡片向下滑出），下面是常驻的操作卡片。两张卡同宽（340px）、中间留 10px 间距，操作卡片只有一行、尽量扁。检索结果列表压得很紧（约 40px 行高、小字号图标与副标题），首屏能多看几条；底部留了内边距，滚到底不会被操作卡片压住。

- 「添加者」按钮是纯图标（人形图标）：PC 与手机**同一套**——点一下在操作卡片**正上方**弹出气泡浮层（宽度与卡片严格一致、高度按内容自适应），再点一下收起，点浮层和按钮以外的地方也会收起。有筛选生效时按钮会点亮，当前筛的是谁写在按钮的 `aria-label` 里。
- 「分类」按钮在最左（树形图标）：点一下弹出**多级分类面板**，外壳、弹出位置与动画和添加者浮层完全一致，宽度与检索卡片严格相等，靠下贴着操作卡片、高度最高不超过检索卡片，装不下时面板内部滚动（滚动条隐藏）。面板里**默认只列出一级分类**（全部折叠，右侧有小箭头）：点带下级的分类是展开 / 折叠它的下一级（本身不筛选，展开状态记在 `expandedKeys` 里，只翻那一棵子树、不重建整棵树）；点没有下级的分类才真的筛选——按「这一级 + 它下面所有级」过滤，面板随即收起、按钮点亮，`aria-label` 写上当前路径（例如「分类筛选：美食 / 早市与美食街」），下次打开时选中的那一支会保持展开；点「全部分类」回到全部。原来的顶部胶囊标签（全部 / 美食 / 酒店 …）与手机端的横滑轨道已整体移除，PC 和手机是同一套交互。
- 足迹页所有会滚动的地方（检索结果列表、分类 / 添加者浮层、搜索结果列表、站内弹窗）都隐藏了原生滚动条（`scrollbar-width: none` 配合 `::-webkit-scrollbar`），滚轮、触摸滑动和键盘翻页照常，检索卡片右下角的圆角也不会再被滚动条压掉。
- 添加标记改成**中心选点**：点「添加标记」，或在地图上**长按**（PC 鼠标长按、手机长按都会触发），地图正中心会出现一个水滴，水滴尖端就是将要落点的坐标，右侧一列是「对号 / 叉号」。这个阶段地图照样能拖能缩，靠移动地图让目标点对准水滴；点对号用当前中心点打开编辑框，点叉号（手机）或按 Esc（PC）取消，确认或取消后地图交互立刻恢复原样。长按有 420ms 阈值，指针移动超过 8px 或地图开始拖动就作废，所以不会和拖动地图、单击、双击放大打架。
- 「分类管理」弹窗底部操作区是「新增一级分类 / 取消 / 完成」：**取消**与右上角的 ✕ 等价，直接关掉弹窗、不保存未提交的改动。
- 地图容器里 Leaflet 自带的 **+ / − 缩放按钮与比例尺（「5 km」那类）已整体移除**（滚轮缩放、双指捏合、右上角「全览」都还在），右下角不再有控件压着版权条。
- 地图上的文字提示分两类：**图标按钮的悬停气泡**跟主题走（浅色主题浅底深字、深色主题深底浅字，都带一点细边框）；**底部提示条**不再跟主题走 —— 全站统一成 8px 圆角矩形 + 深色填充 `#20232a` + 白字，浅色主题也照用，因为提示条是浮在页面之上的一次性反馈，跟着主题变白反而像页面上多出来一张卡片。首页足迹入口那条提示、留言 / 动态 / 书架 / 歌单 / 推荐 / 工作台 / 仓库的提示条都是同一套，普通账号点受限按钮时的「请向管理员申请权限」也在其中。
- 地图上的弹窗（「选择添加者」等）在手机上宽度固定为「屏宽 − 24px」，昵称过长时省略、后面的标记数靠右不换行，不会超出屏幕或被切掉。

### 首页公开动态

- 首页左下角只在桌面端显示近 7 天的公开内容动态，严格按时间倒序排列，最上面是最新记录，不再滚动或使用上下渐隐效果。时间戳使用 `「」` 包裹，时间戳和用户名使用 Error酱主题色但不加粗，时间戳、用户名和正文之间没有额外间距。**管理员**保持默认显示 9 条、单击展开到 20 条（超出可滚动，再次单击收起），双击在当前页面隐藏、刷新首页恢复显示；**普通账号**默认只显示未读提醒（有提醒时绿色呼吸，没有就整块不显示），单击查看最近 9 条日志、双击展开到 20 条、再单击回到只看提醒，刷新首页同样回到只看提醒；**游客**不显示这块区域。桌面端把鼠标移到这块日志上时，指针附近的行会轻微错开（指针上方的行往上让、下方的往下让，最大 2.5px，并按指针在卡片里的左右位置最多再偏 1.5px），字重从 400 抬到最多 500，越靠近指针越明显；鼠标离开后 160ms 内缓动回原位，指针不在上面时它完全静止；系统开「减少动效」时不做这套跟随。
- 只展示公开内容事件：留言、推荐（歌曲 / 书籍 / 网页 / 站内资源）和足迹，按时间倒序取最近 7 天；仓库、书签、笔记、工作台、登录和访问记录不会进入公开动态。游客看不到左下角动态区，接口也不会返回任何动态数据。
- 管理员提醒聚合成「有 N 个待审核注册申请」「有 N 条未读留言」「有 N 条留言待审核」「有 N 个待处理举报」，严格按各自最新时间参与排序，不插队；提醒正文使用与 PING 正常状态相同的绿色，并按“留言 / 工作台”按钮相同的 `3.6s` 节奏呼吸闪烁，处理完成后自动消失。首页、工作台、留言页和动态页每 5 秒刷新一次通知摘要，新举报、新留言和新回复无需手动刷新页面即可更新角标、闪烁和列表。
- 普通账号也会收到自己的互动提醒：管理员发新动态、别人点赞或回复了自己的留言、别人回复了自己的动态评论时，「动态」或「留言」入口会呼吸并显示角标，左下角默认只留一条对应的提醒；未读时该条提醒绿色呼吸。打开留言、动态或推荐后，新内容如果已经出现在当前屏幕里，会完整呼吸 3 次再自动标为已读；如果新内容还在屏幕下方、被筛选隐藏，或位于另一个推荐子页，就继续保持未读并持续呼吸，不会因为只是打开过页面就被清掉。鼠标移入或点击该条仍会立即标为已读。管理员自己不会收到这类提醒，只在展开的日志里保留「更新了一条动态」「更新了一条推荐」这类记录，不会和绿色提醒同时出现在默认视图。留言、动态、推荐统一按这套「新增类事件进提醒、更新类事件只进日志」的规则处理；足迹新增不产生首页提醒。

### 书架（下载电子书）

- 推荐页的第二个子页；独立地址 `/books` 现在会跳回推荐页的书籍标签（不再是一个能停留的页面）。所有访客都能浏览，上传、编辑、删除仅管理员。

- 书架卡片的操作按钮（编辑 / 举报 / 分享 / 下载）收在封面右下角的胶囊里，下载排在最右边；封面下方只保留书名、作者和文件大小，信息不再挤压。普通账号显示举报和自己的下载 / 申请按钮，管理员显示编辑与分享。封面上的这枚胶囊和右上角的格式标签都跟着明暗主题走：浅色主题是半透明白底 + 深色图标，深色主题仍是原来的深底浅字，两边都保留毛玻璃，尺寸和位置不变。
- 封面还带一点**微视差**：往下滚时封面在卡框里朝反方向慢慢漂回来，看起来就像「封面走得比页面慢」，幅度 ±8px。鼠标停在某一本上时它会定住（卡片本身还会抬起 3px，再叠漂移会显得忙）；页面滚不动时（书少到一屏放得下）自然没有任何变化，系统开「减少动效」时整条关掉。用的是 CSS 滚动驱动动画（`animation-timeline`），不支持它的浏览器只会看到静止封面。
- 电子书文件保存在 `data/book_files/`，封面保存在 `data/book_covers/`，文件接口支持 HTTP Range。

### 上传与进度反馈

- 全站统一的上传进度组件（`static/site/progress.js` + `static/site/progress.css`）：单按钮操作用按钮内部填充百分比，多文件用逐条进度行，服务端解析阶段用流动条纹表示还在处理。
- 覆盖音乐上传、留言附件、动态配图、笔记 Word / PDF 导入和工作台文件上传；上传过程中再点一次按钮即取消，已选文件会保留，可以直接重试。
- 全站统一的拖拽上传区（`static/site/dropzone.js` + `static/site/dropzone.css`）：音乐、书架、地图照片与导入文件、留言附件、动态配图、推荐封面和工作台资料都能直接把文件拖进来，拖入时目标区域高亮；拖进来的是文件夹就按类型递归找文件（默认 3 层、单次最多扫描 600 个），不符合类型的文件会跳过并提示，超出各模块单次数量上限的只取前几个。
- 音乐、书架和地图导入在 Chrome / Edge 下改用系统文件选择器（固定选择器 ID），下次上传会回到上次打开的目录；不支持该 API 的浏览器自动回退到原生选择框，行为不变。
- 进度用 XMLHttpRequest 的上传事件计算，请求体和原来的 JSON 接口完全一致，后端接口没有改动。
- 请求体上限 84MB（`MAX_REQUEST_BYTES`，Nginx 侧 `client_max_body_size 84m`）。上传走 JSON + base64，体积约为原文件的 1.37 倍，所以默认 60MB 的音乐、30MB 的固件都能正常送达；各类上限可以在工作台「上传限制」里调整（硬上限 60MB / 100 个）。各页面会读取当前设置并显示真实的限制和报错，超过上限的文件会在上传前直接提示。

- 动态页的悬浮操作区与留言页同一套外壳：夹在「动态编辑区」和「动态卡片」中间（位置和留言页的「全部动态」一致），从左到右是「我的动态 / 开发日志」两枚只带图标的方形按钮 + 筛选下拉 +「写动态」四枚按钮，高度统一为 35px、与留言页的筛选按钮完全一致，同一行靠左排开，两枚图标按钮不再带数字角标；悬停这两枚图标按钮时的文字提示跟随主题（浅色浅底深字、深色深底浅字）。筛选下拉是「全部动态 / 分享 / 评论 / 点赞」：「全部动态」不过滤，「分享」只看从 Error酱分享过去的歌曲 / 笔记 / 固件 / 书籍等资源，「评论」和「点赞」分别列出被任何账号（含管理员自己）评论过 / 点赞过的动态，不再限定「我自己」；筛选是本地即时过滤、选中后写进网址。「开发日志」栏没有可筛的内容、也不能发布，所以筛选和「写动态」在那一栏自动收起。「写动态」和留言页的「发送留言」一样：发布框可见时隐藏（opacity 0），完全滚出视野上方才纯渐变显示，点它淡出、平滑回顶并聚焦输入框；右下角同样是方形毛玻璃「↑ 顶部」按钮，共用 12px 内边距变量（`--mo-float-inset`），距卡片左右边缘严格对称，手机端顶部留白压到 6px。「顶部」按钮同样兼作新互动导航：有未读的新评论且目标还在屏幕下方时变成「↓ 评论」并持续呼吸，点它平滑滚到那条评论；目标进入屏幕后卡片呼吸 3 次再自动标为已读，按钮恢复「↑ 顶部」。定位到的新评论正文会变主题色并闪烁（桌面闪到鼠标移入卡片、手机闪 3 次），整张卡片的方框呼吸保留。提醒里带的是评论 id（动态 id 和评论 id 可能撞号，所以后端同时下发提醒类型来区分），因此不会误标到同号的动态上。
- 动态分两栏，操作区里的图标按钮切换（默认停在「我的动态」）：**我的动态**是手动发布的说说，保留原来的卡片样式、配图、标签、置顶和编辑；**开发日志**是更新日志导入的内容（数据库里 moments.kind 为 log，手动发布的为 post），用更轻的排版——按月份手风琴分组、小字灰字、无卡片无阴影，每行只有一个 git commit 节点图标 + 时间 + 标题，点开才展开当日条目；列表上方不再有「展开全部 / 收起全部」按钮，第一组月份直接衔接在悬浮操作区下方，不留空位。切栏只在前端分流，不刷新页面、也不重新请求，地址栏会记下 ?kind=log。这两枚按钮和筛选 /「写动态」同排在「动态编辑区」与「动态卡片」之间的悬浮操作区里（PC 和手机同一套，滚动时一起吸附在顶部）；发布框只在「我的动态」里出现，筛选也只在那一栏生效。**游客在「开发日志」里能看月份、日期和每一条日志的概述**（时间 + 标题）：月份手风琴照常开合，默认同样展开最近一个月；只有每一条日志右边的展开箭头对游客上锁 —— 点它会提示「请登录后操作」并保持收起，明细正文对游客不会下发到页面里。
- 动态：记录说说和日志，默认最多 9 张配图、单张 5MB、合计 15MB（可在工作台「上传限制」调整，图片也可以直接粘贴截图），支持标签、置顶、编辑和删除。**两栏对游客都全文开放**：正文、配图、标签、属地都能看，普通账号的名字只保留最后一个字（例如「牛大能」显示为「**能」）、点赞者名字同样脱敏。**评论 / 回复区也对游客公开**（正文照常下发，评论人名字同样只保留最后一个字），评论输入框、「回复」按钮、「发送」按钮不给游客，点赞保留大拇指图标（游客点了提示「请登录后操作」），分享卡只留封面与标题加一句「请登录后操作」。游客默认停在「我的动态」，只是发布和编辑仍仅管理员。卡片头像用透明底的角色立绘（和标签页图标同一张画的高清版，桌面 40px / 手机 36px）：不垫底色、不做圆形裁剪、整张立绘原样显示（立绘底部原本是被原图裁断的胸像，那里做了一点渐隐过渡），「Error酱」昵称那一行的中心与头像中心严格对齐。点赞和留言页同一套：线框大拇指（未赞灰、已赞只换主题色描边、不显示数字），右边跟点赞者名字（最多 3 个，超出收成「等 N 人」）。评论区支持一层回复：每条别人的评论下面点「回复」就地展开「回复 @某某…」输入框（同一时间只展开一个），提交后作为子回复缩进显示在被回复的评论下方、带「回复 @某某」标记，回复的回复也并回该条评论下，不会出现三层缩进。行动区按作者区分——自己写的评论 / 回复显示「删除」（二次确认），别人的评论只显示「回复」，不会在别人的评论下面挂删除按钮。评论不会IP属地。动态本身的「举报 / 置顶 / 编辑 / 删除」收进卡片右上角的「三个点」菜单，和 Error酱 / 时间 / 属地同一行（管理员看到置顶 / 编辑 / 删除，其它账号和游客看到举报），PC 悬停卡片才显示、手机常驻，菜单向下展开。手机端评论输入框和发送按钮压得更矮，两者保持同一行，键盘弹出后输入区域会自动滚动到可见位置。
- 留言附件和动态配图的图片都按朋友圈九宫格排：1 张保持原比例、2-4 张两列、5-9 张三列，格子统一裁剪成正方形，超过 9 张时第九格右下角显示「+剩余数量」；留言里 PDF / 文本这类附件仍是文件条，点开弹预览（图片不显示文件名，附件保留名字方便确认）。两处的图片查看器是同一套全屏「灯箱」：原图独立展示、四周没有白色外框和多余元素，左右有上一张 / 下一张按钮（PC 方向键也能翻页）和「第几张 / 共几张」计数，双击 / 手机连点两下放大到 2 倍，再双击还原；电脑上还能滚轮缩放、放大后按住鼠标拖动平移，手机上是双指捏合缩放 + 单指拖动平移，缩放范围 1~5 倍，放大缩小外框不会跟着动。
- 设备信息：留言和动态卡片头部会在时间后面跟一句设备来源，默认按提交时的浏览器 User-Agent 自动识别成「来自 <系统>」：鸿蒙（先判 `OpenHarmony` / `HarmonyOS`，鸿蒙 4.x 及以下的 UA 里同时带 `Android`，所以优先于 Android）→ Android → iOS（iPadOS 13+ 把自己报成 Macintosh，靠同一个 UA 里的 `Mobile` 认出来）→ ChromeOS → Windows → macOS → Linux；认不出来（含空 UA 或非浏览器客户端）记「来自 Web」。只认系统、不认浏览器，所以 Chrome / Firefox / Edge / QQ 浏览器在电脑上都是「来自 Windows」。**「设备平台」和「IP属地」一样是可选公开项**：编辑区里的「设备平台」勾选框对所有人开放，默认不勾选，勾了才会把这一条的设备来源公开到卡片上（不勾就落空值、卡片上不显示）。管理员登录时编辑区还会多出一个自定义名称输入框（只有管理员看得到，输入框里不出现滚动条），填入内容会自动勾选「设备平台」，勾上就用自定义名称（例如「iQOO 12 Pro」），留空则回到自动识别。这个输入框由 `site:device_name` 权限控制（管理员天然具备，可以在「工作台 → 账号权限」里单独开放给某个普通账号，或者在「角色」里整批给普通账户），没这个权限的账号看不到输入框，伪造 `device_info` 也会被后端直接忽略。

- 互动提醒文案：直接回复留言提示「回复了你的留言」，回复某条回复提示「回复了你」，有人评论动态（包含回复动态里的评论）提示「评论了你的动态」；这些文案用于首页左下角提醒。**Webhook 只推「新的留言 / 回复顶层留言 / 顶层动态评论」**：楼中楼（回复某条回复、回复某条评论）是两个人之间的对话，只进站内提醒、不再往外推；删除类操作（删除留言、删除标记等）同样只记内容事件、不推 Webhook，避免手机上收到一堆噪音。

- 留言和动态支持显示 IP 属地：国内公开到省级、国外显示国家 / 地区，一律直接显示属地名（例如「广东」），不再写「IP 属地：」前缀。编辑区里的复选框文案就是「IP属地」四个字（原来括号里的说明已删掉，规则没变：国内到省、国外到国家 / 地区，完整 IP 不对外返回），每次进入页面都默认不勾选，不记忆上次选择，只有本次明确勾选才会公开；完整 IP 只入库用于安全审计，不会通过任何接口对外返回。属地解析优先使用 `INVENTORY_AMAP_KEY`（高德 IP 定位）和国内数据库兜底，海外 IP 再使用 ipwho.is 解析；不配置高德 Key 时国内和海外仍会尝试兜底解析。
- 全站提示、确认和输入操作统一使用 Error酱 站内对话框，不再调用浏览器原生 `alert / confirm / prompt`；登录、举报提交、举报处理、删除确认和批注输入等场景保持同一套明暗主题与移动端样式。
- 站内对话框出现时有一下短促的入场（约 220ms 的强 ease-out，从 0.96 放大到 1 并淡入）；系统开启「减少动效」时自动降为纯淡入。同一条动效词汇（--dur-fast 160ms + 强 ease-out；动效曲线、时长、圆角档位、实心主色块上的文字色（--on-accent）和提示条的深色填充（--toast-bg / --toast-ink）都集中在 static/fonts.css，别在各页手写）现在也用在另外四处：各页提示条从下方 8px 淡入、消失时原路淡出（6 个页面共用一条 keyframe），侧栏状态小窗口从胶囊左上角放大淡入、关闭仍瞬时，开发日志展开月份 / 单条时淡入（收起仍瞬时），右下角「顶部 / ↓ 更新」按钮改掉「声明了过渡但因为 display:none 永远不播」的老毛病、真的淡入淡出；这四处开启「减少动效」时都只保留淡入淡出，不做位移与缩放。顺带修掉了一个长期存在的小毛病：「提示 / 确认」弹窗里以前一直挂着一个空白输入框（约 116px），看着像要你填东西——原因是它靠 `hidden` 属性隐藏，而作者样式里的 `display: block` 把浏览器默认的 `[hidden] { display: none }` 盖掉了。
- 留言和动态的文字、图片与附件默认只读：只有发布者本人和管理员能下载、复制或另存，其他访客只能在页面内查看（图片点开为站内查看弹窗）。前端加了防右键、防拖拽、防复制处理，属于劝阻级别，无法阻止截图或开发者工具直接抓取。
- 早期那版「小屋」原型页（`static/hub.html`，把留言 / 照片墙 / 音乐 / 推荐四栏塞在一页）已经彻底删掉：留言、推荐都在正式页面里，照片墙归工作台，音乐由「歌单」接替，仓库里不再保留这个旧页面。

### 推荐（页面外壳）

- 首页公共入口是「留言 / 推荐 / 动态」三个：页面 `/downloads` **没有顶部导航栏**，四个子页面直接铺满整个窗口；左上角四枚悬浮的纯图标按钮切换 **歌曲 / 书籍 / 网页 / 站内资源**（尺寸、位置与留言、动态页左上角的悬浮按钮同一套：35px 方形、圆角 10px、内容列两侧各内缩 28px，鼠标悬停显示提示文字，提示框浅色主题浅底深字、深色主题深底浅字，触摸设备不显示）。右上角还有一枚悬浮的「新增」按钮，图标是「上传」，文字随子页一起渐入渐出（**上传 + 歌曲 / 书籍 / 网页 / 站内**，仅站长可见、可点），点它直接打开当前子页的新增 / 上传弹窗。子页里的编辑弹窗（歌曲 / 书籍 / 网页 / 站内共用同一套）打开时，左上 4 枚 + 右上 1 枚悬浮按钮会整条向上滑出屏幕给弹窗让位，弹窗关掉后再滑回来（子页在 iframe 里，靠 `postMessage` 通知外壳）。手机端这排按钮就贴在页面最上沿（`top: 6px`，不再叠加 `safe-area-inset-top`），充当悬浮顶栏，正文顶部留白同步压到 50px。
- 四个子页在打开推荐页时就已经全部加载好，切换只是翻转显隐，所以来回点不会重新加载、也不会打断正在播放的歌曲；地址栏会记下 `?tab=music|books|web|resource`。正文列宽、页面底色和雨景都对齐留言与动态页（同为 760px 居中），正文顶部留出一条刚好躲开悬浮按钮，往下滚时内容从按钮下面穿过。`/music`、`/books`、`/recommendations` 就是这四个内嵌子页本身（推荐页的 iframe 直接引用它们，不是另做的一套旧页面），所以路由保留；但它们不再是任何入口的落点：更新日志点这几类只会原地切标签或提示「请在推荐页查看」，中键 / 右键新开标签页也只会落在 `/downloads?tab=…`。其中 `/music` 和 `/books` 连「能停留的页面」都不再是：不带 `?embed=1` 直接打开会 302 跳回 `/downloads?tab=music|books`（原有的 `focus` 定位参数照搬），所以这两个地址的顶栏连同原来那个「举报与投诉」在浏览器里已经看不到了；`/recommendations` 不带 `?view=` 时仍是那张「全部 / 网站与工具 / 电影 / 动漫 / 站内资源」的独立页（电影 / 动漫目前只有这儿看得到），所以保留原样，只把顶栏里的「举报与投诉」删掉。举报入口由此从整个推荐模块退场：页面级不再有任何入口，只保留单条歌曲 / 书籍 / 网页卡片上的「举报」（游客和普通账号都能点）。
- 某一栏有新内容时，对应的图标按钮会显示数字角标、并按站内统一的 3.6s 节奏呼吸；只打开这一栏、但新内容还不在当前屏幕里时不算已读，角标和呼吸会保留到内容真正进入屏幕并完成 3 次呼吸。新内容已经在当前屏幕里时，图标和卡片一起呼吸 3 次后自动清零，首页「推荐」入口的总角标同步减少。**「网页」和「站内资源」两栏分开计数**：分享出来的站内资源只算「站内」那一颗的角标，站点 / 工具只算「网页」那一颗，两栏各自按内容是否真正进入屏幕来清除。首页「推荐」按钮上的数字仍是歌曲 / 书籍 / 推荐内容三个模块未读数之和（推荐按总数算，不受拆分影响）。
- 角标和呼吸沿用站内那套通知：普通账号会收到「管理员上传了歌曲 / 上架了电子书 / 新增了推荐」，管理员自己上传的内容不产生提醒，和留言、动态是同一套规则；新上传的内容卡片本身也会呼吸，已经在屏幕里时呼吸 3 次后自动标为已读，鼠标移入或点击仍会立即清除；不在当前子页或还在屏幕下方时继续保持未读。
- 「+站内」打开的是分享选择弹窗：分笔记 / 歌曲 / 电子书三栏列出站内内容，点「分享」就把这一条分享成一张「站内资源」卡片（站内资源只能这样产生）。
- 四个子页右下角都是**和动态页同一颗「顶部」按钮**：同样的方形毛玻璃（48×58、圆角 10px）、同样的位置（落在 760 内容列内侧右下角，和左上角悬浮按钮共用 28px 内缩，左右完全对称）、同样的行为（往下滚才出现、点击平滑回顶）。有新内容（新歌 / 新书 / 新推荐）还在屏幕下方时，它会变成**持续呼吸的「↓ 歌曲 / ↓ 书籍 / ↓ 推荐」**，点一下平滑滚到那条新内容；滚到之后自动变回「↑ 顶部」，目标卡片再呼吸 3 次后标为已读。

## 账号与权限

默认不设置密码时是免登录模式，局域网内直接使用。设置 `INVENTORY_PASSWORD`（或运行 `python tools/set_password.py`）后会启用登录：

| 身份 | 可访问内容 |
| --- | --- |
| 游客 | 首页、参考项目、留言（正文全开，普通账号名字脱敏、回复照常显示）、动态（两栏正文全开，名字脱敏、评论与回复照常显示）、推荐页（歌曲 / 书籍 / 网页 / 站内资源元数据，网页可点开）；不能播放歌曲、下载电子书或打开站内资源链接。留言、动态、歌曲、书籍和推荐内容都可以提交举报，游客也不需要登录 |
| 普通账号 | 默认拥有公开页面浏览、已审核留言和动态查看、歌单播放、留言发言和 `map:write`；其余写 / 管理权限由「全部权限 → 普通账户」角色统一发放 |
| 管理员 | 全部模块；站长可以在工作台把「管理员」权限授予第二个账号 |

- 注册只需要填写用户名和密码；昵称默认显示用户名，登录后可在首页账号菜单里修改（2-16 位、支持中英文/数字/常见符号、全站唯一且会做敏感词检查，同一账号每 30 天可改一次）。
- 注册申请不限网络：手机流量、公司网络、家里 WiFi 都能提交，同一 IP 24 小时内最多 3 次，并且同一 IP 同时只能有 1 条待审核申请（计数写在数据库里，重启不清零，额度用完提示“明天再试”）。
- 注册后进入待审核队列。站长/管理员在工作台「账号权限」页里同意、拒绝、停用、重置密码或删除账号。「全部权限」里按游客 / 普通账户 / 管理员三个角色维护默认权限，管理员固定全部权限、不可收回；「全部账户」里还能对单个账号设置“继承角色 / 允许 / 禁止”三态覆盖，有效权限 = 角色默认 + 单独允许 − 单独禁止。所有操作都会写入审计日志。
- 权限点覆盖仓库、书签、笔记、工作台（含提示词）、地图（新增/改全部/管分类）、站点内容（歌单、书籍、链接、照片）以及「管理员」；普通账户角色默认 `map:write`，角色页只分配写 / 管理类权限，查看类权限仍在「全部账户」里按账号单独授予；留言审核、动态、推荐和地图导入不开放授权，仅管理员可用。书籍阅读器下线后原来的 `books:read` 权限点一并删除。
- 游客公开范围由「账号权限 → 全部权限 → 游客」控制：默认能进入留言、动态、推荐和参考项目页面，留言与动态的正文（含配图、属地）、评论与回复都对游客开放，只是普通账号的昵称、点赞人和评论人名字只保留最后一个字（点赞保留大拇指图标，点了提示「请登录后操作」）；播放流、电子书下载、站内资源跳转链接和非图片附件仍然要求登录。游客遇到的登录提示统一成一句「请登录后操作」：首页足迹入口、歌曲下载、播放、点赞、打开站内资源都用这同一句；留言 / 动态 / 歌曲 / 书籍 / 推荐内容的举报都对游客开放，不再要求登录。地图对游客完全关闭（足迹入口和 PING / FPS 仍会显示，点击入口提示「请登录后操作」；直接访问 `/map` 或地图接口会被拦截）。
- 敏感词库在工作台里维护，内置政治、暴力、辱骂、色情、广告几类基础词，可自行增删；匹配会忽略大小写、全角半角和空格/符号干扰，昵称命中会拒绝修改，留言昵称或正文命中直接拒发，管理端有测试框。
- 有待审核注册时，首页工作台入口会显示紫色呼吸高亮和数量角标，审核完自动消失（不需要邮件系统）。
- 工作台「账号权限 → 通知设置」可以配置 Webhook 推送，把「新注册申请 / 新待审附件 / 新留言（含回复顶层留言）/ 新的标记点 / 安全提醒」推送到手机或群里（楼中楼回复和删除类操作不推）：安全提醒包含登录失败（同一 IP 5 分钟内失败 5 次，30 分钟内不重复）和敏感词拦截（同一场景 10 分钟内不重复）。支持企业微信、钉钉、飞书群机器人、Bark（iOS）、Server酱（微信）和通用 JSON Webhook；可以发送测试通知，最近的推送成功/失败记录也会保留在页面里。没有配置时只有站内呼吸提醒，不影响使用。
- 密码只保存 PBKDF2-SHA256 哈希；会话使用 HMAC 签名 Cookie（HttpOnly + SameSite=Lax，默认 7 天，勾选“记住我”为 30 天）。同一账号最多同时保持 1 个电脑端 + 1 个手机端（平板算手机端）会话：同类型设备再次登录会让旧会话立刻下线；退出登录、重置密码、停用账号都会立即失效。管理员（站长和具有「管理员」权限的账号）的会话还绑定登录时的来源 IP：换了网络，下一次请求就会被下线并要求重新登录（普通账号不受影响，可以在手机和家里网络之间自由切换）。升级到这套会话机制后，旧会话需要重新登录一次。
- 管理员密码可以在站内自助修改：工作台「账号权限 → 登录密码」输入当前密码和新密码即可，改动写进 `data/auth.json`（PBKDF2-SHA256 哈希，8-128 位）并**立即生效、不需要重启服务**；改完其它设备上的管理员会话会失效。`INVENTORY_PASSWORD` 环境变量只在 `data/auth.json` 还没有密码哈希时充当初始密码，站内改过一次之后就由 `auth.json` 接管（想回到环境变量模式，删掉 `auth.json` 里的 `password_hash` 即可）。会话签名密钥同样以数据库 `app_meta.auth_secret` 为准，重启不会掉线。
- 登录失败 5 次会锁定 5 分钟（按 IP 统计，不会因为大量新 IP 出现被整体清零）；停用账号后已有会话立即失效。
- 服务器侧用 fail2ban 自动封禁：同一 IP 10 分钟内触发 10 次接口限速就封 2 小时（`/etc/fail2ban/jail.local`，站点日志走 `/var/log/nginx/errorjiang.error.log`），管理员的常用出口和 VPN 网段写在 `ignoreip` 里永不误封。
- 写接口按 IP 限速，留言限制为每 IP 每分钟 5 条；游客能查看已审核的留言正文，但无法触发留言写入，也看不到回复区。

## 快速开始

环境要求：Windows / macOS / Linux，Python 3.10 或更高版本。

Windows：

```bat
start-inventory.bat
```

也可以使用 `run.bat`。启动脚本会在需要时自动安装 Word / PDF 文档转换依赖。

macOS / Linux：

```bash
chmod +x run.sh
./run.sh
```

或者直接运行：

```bash
python -m pip install -r requirements.txt
python app.py
```

启动后访问 <http://127.0.0.1:8000>。

### Docker（可选）

```bash
docker compose up -d --build
```

数据仍然保存在项目目录的 `data/` 文件夹中。

### 手机局域网访问

1. 手机和电脑连接同一个 WiFi。
2. 启动服务后查看启动提示，或用 `ipconfig`（Windows）/ `ifconfig`（macOS / Linux）找到电脑的局域网 IP。
3. 手机浏览器打开 `http://电脑IP:8000`。

Windows 首次访问如果被防火墙拦截，需要放行 TCP 8000：

```text
netsh advfirewall firewall add rule name="Errorjiang 8000" dir=in action=allow protocol=TCP localport=8000
```

### 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `INVENTORY_HOST` | `0.0.0.0` | 监听地址 |
| `INVENTORY_PORT` | `8000` | 监听端口 |
| `INVENTORY_PASSWORD` | 空 | 设置后启用登录 |
| `INVENTORY_SECRET` | 自动生成 | 会话签名密钥，保存在 `data/auth.json` |
| `INVENTORY_ALLOW_OPEN` | 关闭 | 应急开关：`data/auth.json` 存在但读不出来时默认拒绝启动，设为 `1` 才允许强行启动（此时全站免密，仅限临时排查） |
| `INVENTORY_TRUST_PROXY` | 关闭 | 走 Nginx 反代时读取 `X-Forwarded-For` / `X-Forwarded-Proto` |
| `INVENTORY_SECURE_COOKIES` | 关闭 | 强制使用 Secure Cookie（HTTPS 环境） |
| `INVENTORY_ACCESS_LOG` | 关闭 | 打开访问日志 |
| `INVENTORY_LOG_DAYS` | `180` | 内容事件与访问明细的保留天数，到期自动清理 |
| `INVENTORY_MAP_PUBLIC` | `1` | 设为 `0` 时地图和地图接口仅管理员可访问 |
| `INVENTORY_AMAP_KEY` | 空 | 高德开放平台「Web 服务」Key，用于地图右上角「搜索」里的 POI 查询，以及留言 / 动态的国内 IP 属地解析；不配置时 POI 搜索会提示先配置 Key，IP 属地仍会使用国内和海外兜底解析 |

## 公网部署

推荐结构：

```text
浏览器
  -> Nginx（80 / 443）
  -> 127.0.0.1:8000
  -> systemd 服务 errorjiang
  -> <应用目录>/app.py
  -> <应用目录>/data
```

- 反向代理示例：`deploy/nginx-errorjiang.conf`
- systemd 单元：`deploy/errorjiang.service`
- 只监听回环的 Docker 方案：`docker-compose.prod.yml`
- 管理员入口白名单脚本：`deploy/nginx-allow-ip.sh`（配合 `deploy/nginx-errorjiang-admin-allow.conf`）
- 外出访问后台的 WireGuard 通道：服务端 `wg0`（`10.66.0.1/24`，监听 UDP 51820），VPN 网段 `10.66.0.0/24` 已在白名单内；客户端配置放在管理员本机桌面 `Error酱-VPN\` 目录
- 手机应急 SSH：单独一把密钥 `phone-termius`（公钥在服务器 `/root/.ssh/authorized_keys`，私钥在管理员本机桌面 `Error酱-VPN\手机SSH\`），配 Termius 用，白名单把自己挡住时靠它进服务器放行 IP；丢手机就删掉 `authorized_keys` 里带 `phone-termius` 的那一行
- 手机上改白名单的短命令：`deploy/ea-allow.sh` 安装成 `/usr/local/bin/allow`，用法 `allow list` / `allow open 2h` / `allow strict` / `allow add 1.2.3.4 2h`（Termius 免费版没有 Snippets，短命令免去手打长路径）

服务器上至少要做三件事：把 `INVENTORY_PASSWORD` 写进 `/etc/errorjiang.env`、让应用只监听 `127.0.0.1`、用 Nginx 转发并配置 HTTPS。完整的部署过程见 `DEPLOYMENT_LOG.md`，面向新手的服务器维护步骤见 `ERRORJIANG_MAINTENANCE.md`。

管理员入口的 IP 白名单是「可开关」的：当前处于**开启**状态（只有名单内的 IP / 网段能进 `/login`、`/logout`、`/workbench`、`/api/workbench`、`/api/prompts`、`/api/admin`），用 `sudo bash deploy/nginx-allow-ip.sh strict` 收紧、`open` 放开；`add 1.2.3.4 2h` 可以临时放行某个 IP，`open 2h` 可以「临时全部放开，到点自动切回 strict」（去网吧、借别人电脑时的应急用法），到期由 systemd 定时器自动执行、`remove` 也能手动撤销，脚本每次改动都会先备份、`nginx -t` 通过才 reload，失败自动回滚。游客注册申请（`/api/register`）和普通账号登录（`/api/member/login`）**不在**白名单管辖范围内，任何网络都能用，只受各自的接口限速约束。

注意白名单只拦「进后台」这一步：浏览网页、普通账号登录注册都不受影响，普通账号的会话也不绑 IP。**管理员会话额外绑定登录来源 IP**（2026-10-10 起）：来源网络一变，下一次请求就会被判定失效、需要重新登录；而重新登录本身要过白名单，所以在外面的正确做法是先连 `wg0` 那条 WireGuard 隧道（VPN 网段在白名单里，连上就等于在受信任网络），完整步骤见站内笔记《Error酱管理员入口白名单：喂饭版操作笔记》第五节。

## 界面约定

- 全站统一主题：默认跟随系统深浅色，首页切换后会通过 `localStorage` 同步到其他已打开的页面；登录页、注册申请页、留言、动态、推荐和歌单都跟随同一套配色（注册页不再固定浅色）。
- 首页页脚的字体说明会贴到底部并与足迹入口底端对齐，下面保留备案号占位行；备案完成后只需替换占位文字。
- 在 2K / 125% 等桌面显示环境下，首页标题、简介、模块入口和“参考项目 / Error酱源码”会作为整体垂直居中，页脚和地图等固定元素不参与内容组居中。
- 首页 PING / FPS 是浏览器端实时测值；FPS 使用 `requestAnimationFrame`，会受屏幕刷新率限制，60Hz 屏幕显示约 60F 属于正常。手机端不显示 PING / FPS，PC 端保持显示且文字不加粗。
- 标签页文字和首页入口保持一致：留言、动态、推荐、仓库、书签、笔记、工作台，地图页面和首页足迹入口的悬停提示都显示「足迹」；推荐页内嵌的页面仍分别认领「歌单 / 书架 / 推荐」的标签页名字。首页三个公共功能按钮的文字做两端对齐（两个字撑满三个字的宽度），按钮宽度收到刚好包住文字。全站标签页图标（浏览器标签上的那张缩略图，`static/site/error-chan-favicon.png`，`/favicon.ico` 也走同一个文件）用的是和动态头像同一张角色立绘，底部同样做了 30% 渐隐——渐隐是直接烤进 PNG 透明通道的，所以每个页面（包括新标签页打开的页面）都是同一张带渐隐的图标；改图标内容后记得同步把各页 `?v=` 版本号加一，否则浏览器会继续用缓存的旧图标。
- 首页三个公共入口是留言、动态、推荐，都是普通链接：点击在当前标签页进入，把它拖到浏览器顶部标签栏（或中键 / Ctrl+点击 / 右键在新标签页打开）会新开一个标签页进入。
- **留言 / 动态 / 推荐三个页面没有顶部状态栏**：原来那条带模块名、图标、「共 X 条」和「举报与投诉」入口的横条已从 DOM 里删掉，相关计数绑定也一并清理；下面内容自然上移，页面自己留 16–20px 顶部留白并避开刘海屏安全区。单条内容的举报入口不受影响（卡片上的「举报」仍走站内举报弹窗，`/reporting` 说明页也照旧）。
- 留言页的悬浮筛选按钮、动态页的两栏标签和推荐页左上角的四枚图标按钮都是**常驻悬浮**的同一套：尺寸 / 间距 / 圆角一致（推荐页的图标按钮严格对齐留言、动态页的悬浮按钮），自带主题底色 + 毛玻璃 + 极浅底影，滚动时不会消失，也不会压住下面第一条内容。
- 首页四个私有模块入口（仓库、书签、笔记、工作台）固定预留缩略图高度：普通账号和游客没有缩略图时也保持和管理员一样的高度，刷新首页或从动态、留言等页面返回时不会出现方框由矮变高的跳变；预留的占位不占宽度，表情和文字始终落在按钮正中间。
- 四个入口的缩略图规则一致：最多显示 5 个圆形缩略图，超过 5 个时再跟一个「+N」数量圆点（鼠标悬浮可以看到完整标题）。仓库用元件图片，书签用站点图标，笔记用正文里的首张图片、没有图片就用标题首字（图片加载失败时会保留首字，不会出现空圈），工作台没有图片封面，用最近 5 份资料标题（没有标题时用文件名）的首字母。
- 弹窗和编辑页统一采用「固定头尾」：标题行（含关闭按钮）在滚动时贴在弹窗顶部，底部操作行（删除 / 取消 / 保存）常驻贴底，只有中间的表单内容滚动。
- 实现方式参考 `static/workbench.css` 的 `.wb-modal-head` / `.wb-modal-actions`，以及 `static/map.css`、`static/music.css`、`static/prompts.css` 里对应的 sticky 规则；新增编辑弹窗时按同样方式处理（`position: sticky` + 负 margin 抵消弹窗内边距）。
- 手机端按钮的点按反馈统一自绘（`static/fonts.css`，所有页面都会加载）：关掉浏览器默认的矩形 tap highlight，改用跟随按钮自身圆角的 `:active` 反馈（浅色主题压暗、深色主题提亮，圆角越大的按钮反馈形状就越圆），圆角按钮、胶囊按钮和圆形图标按钮都不会再闪出直角方块；包着输入框的 `label` 不参与，避免打字时整块闪一下。桌面端（有指针的设备）另有一套 hover 反馈：真正的「动作按钮」—— 发送 / 发布 / 发布留言 / 上传 / 保存 / 确定 / 取消 / 提交（`mg-btn` / `mo-btn` / `mu-btn` / `rec-btn` / `wb-btn` / `nt-btn`、书签的 `pin-*` 按钮、登录与注册的提交按钮、站内对话框按钮、举报提交、地图弹窗里的按钮）鼠标移上去抬高 2px，按下去回到原位再收 1%，只动 `transform`、不改边框主题色；图标按钮、筛选与分段控件、点赞、图片墙格子、「三个点」更多菜单、地图工具栏都不参与（一排一起跳会变成噪音）。首页「留言 / 动态 / 推荐」那三个按钮保持它们原来那套（抬高 + 边框变主色）不动。以上在系统开「减少动效」时全部关掉。
- 在原来的悬停反馈之上，全站动作按钮现在共用一层 `static/site/button-effects.js` / `button-effects.css`：按下收至 92%，松手带一次轻微过冲回弹；主操作按钮在桌面端向指针做不超过 4.5px 的磁吸，并浮起跟随当前主题的 Error酱 紫色光晕；点击时从指针落点扩散一圈液态色波。运行时新插入的按钮也会被自动接管，触屏不启用磁吸，地图标记、聚合点和留言 / 动态的图片墙格子明确排除在按钮反馈层之外（点图片不再有按下缩回弹）。
- 登录 / 注册 / 留言 / 动态 / 笔记保存的提交按钮在请求期间显示加载环，成功后形变成对勾并闪一次主题紫高光，同时从按钮边缘爆开 12 颗主题紫色微粒。所有删除入口现在直接在原按钮上长按 900ms，进度从左向右填满才执行，中途松手回退，不再弹二次确认框；危险按钮用红色填充、其它按钮用主题紫。笔记的「放弃修改」、地图的「保存位置」等普通确认仍是一次点击，键盘触发的删除也保持即时。系统开「减少动效」时关闭磁吸、液态扩散和微粒，只保留必要的状态反馈。
