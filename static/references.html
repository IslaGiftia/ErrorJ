Error酱参考与搬运来源

Error酱并不是从零原创，功能主要参考、搬运并组合以下开源项目。这里是截至 2026-10-08 的开发过程中实际参考、搬运或依赖的项目；只借鉴交互、未复制代码的会单独注明，各项目的代码与设计仍遵循其原始许可证。

Error酱 / ErrorJ（本站自身）

本站源码仓库，持续记录 Error酱 的开发、部署和功能更新。截至 2026-10-08 已包含：仓库、书签（Firefox 增量导入）、笔记（Word / PDF 导入、HTML 导出）、工作台（资料 / 固件 / 维修 / 提示词 / 账号权限 / 内容审核 / 下载申请 / 日志）、地图、歌单、书架、照片墙、留言、动态、推荐、参考项目管理、游戏大厅、注册登录与权限体系；最近补充首页近 7 天 9 条静态动态、用户名脱敏、限时分享链接、逐账号下载审批、下载申请 Webhook、聚合管理员提醒、移动端音频时长修复、PING / FPS 状态面板、2K / 125% 布局微调、工作台日志和登录失败 / 敏感词安全提醒。

MirrorChyan/user-frontend

参考并搬运首页雨滴动画、入口悬停展开和卡片层次表现。

InvenTree

参考并搬运元件、项目、附件、库存流水和扩展接口的数据组织方式。

Part-DB

参考并搬运项目 BOM、元件资料、事件记录和电子元件管理流程。

BookStack

参考并搬运独立附件、下载访问，以及内容与文件分离的设计思路。

Snipe-IT

参考并搬运维修记录的日期、状态、费用、处理方和附件字段。

PinMark

书签模块的参考工程：借鉴浏览器书签的目录树、卡片 / 导航视图和书签整理交互。Error酱 在此基础上实现了纯增量导入（Firefox 只补新增网址，不回滚整理结果）、分类拖拽排序和备注标签，具体授权以原仓库说明为准。

firecrawl/anydoc

笔记的 Word / PDF 导入依赖（MIT 许可证，requirements.txt 中的 firecrawl-anydoc）：把 DOC / DOCX / PDF 转成结构化内容，再由 Error酱 渲染成站内 Markdown 并提取内嵌图片。

esptool-js

作为后续浏览器在线烧录 ESP 系列固件的候选搬运实现。

Memos

动态（说说 / 日志）参考其卡片式时间线、置顶和标签组织，MIT 许可证；只借鉴交互，代码由本项目自行实现。

Ech0

同类中文动态 / 说说实现参考，AGPL-3.0 许可证；只参考产品形态和交互，未复制其代码。

Artitalk

参考其轻量说说的输入、图片上传与时间线交互，MIT 许可证；未直接引入其代码。

Caro-Board

搬运其五子棋双人对战、人机模式和点击落子逻辑，采用 MIT 许可证。

2048

2048 的规则、合并逻辑与数值设计来源，MIT 许可证；本站按同一规则用原生 JS 重写了界面、计分、最高分存档和移动端滑动。

Leaflet

地图渲染引擎，BSD-2-Clause 许可证，以静态文件方式引入本站地图模块。

Leaflet.markercluster

标记聚合插件，MIT 许可证，用于地图上大量标记的聚合显示。

uMap

参考其地图编辑的功能组织：分类着色、弹窗编辑、GeoJSON 导入导出。uMap 使用 AGPL-3.0，本站只参考交互设计，不复制其代码。

Leaflet.Storage

参考其“前端编辑地图要素、通过接口保存”的数据组织思路，WTFPL 许可证。

geo-notes

参考其“标记 + 分类 + 备注”的个人地图交互，MIT 许可证。

Leaflet.ChineseTmsProviders

参考国内瓦片服务在 Leaflet 中的接入方式，本站只内置了高德矢量与卫星两套配置。

APlayer

参考其音乐播放器的功能组织：封面、播放列表、循环和随机播放，MIT 许可证；本站按同样的功能集自行实现，没有直接引入。

Navidrome

参考其自托管音乐库的浏览与播放体验（歌单优先、封面、正在播放），GPL-3.0，仅作交互参考。

music-metadata

参考其音频标签与内嵌封面的解析范围（MP3 ID3、FLAC PICTURE、M4A covr 等），MIT 许可证；本站用 Python 标准库实现了对应的解析。

Casbin

参考其「主体 / 对象 / 动作」的权限策略模型和角色继承思路，Apache-2.0 许可证；本站用 SQLite 权限表实现了简化版，没有引入依赖。

sensitive-word

参考其 DFA/Trie 敏感词匹配和全半角、符号干扰归一化思路，Apache-2.0 许可证；本站用 Python 标准库实现了相近的匹配器，词库由管理员自行维护。
