Error酱参考项目

Error酱并不是从零原创，功能主要参考以下开源项目。这里是截至 2026-10-13 的开发过程中实际参考或依赖的项目；只借鉴交互、未复制代码的会单独注明，各项目的代码与设计仍遵循其原始许可证。2026-10 的几轮重构删掉了小游戏模块与站内电子书阅读器，对应的参考条目也一并移除。

Error酱 / ErrorJ（本站自身）

本站源码仓库，记录 Error酱 的开发、部署与功能更新（具体变更明细记在仓库的 DEPLOYMENT_LOG.md 与 README 里）。截至 2026-10-13 的站内模块：仓库（元件 / 项目 / 出入库 / BOM）、书签（Firefox 增量导入）、笔记（Word / PDF 导入、HTML 导出、智能排版）、工作台（资料 / 固件 / 维修 / 照片墙 / 提示词 / 账号权限 / 留言审核 / 举报处理 / 上传限制 / 日志）、地图（足迹标记、分类与 GeoJSON 导入）、留言、动态（我的动态 + 开发日志）、推荐（歌曲 / 书籍 / 网页 / 站内资源四个子页），以及注册登录与权限体系。近期改动比较大的几轮：留言与动态重构成 760px 居中列表，操作收进「三个点」菜单，筛选与发布按钮改成常驻悬浮，右下角「顶部」按钮兼作新内容导航；「下载」页改名「推荐」，删掉顶部导航栏、四个子页铺满窗口，左上角四枚悬浮图标按钮切换子页、右上角「上传 + 歌曲 / 书籍 / 网页 / 站内」常驻；歌曲页删掉搜索框与底部播放条，改成点封面播放 / 暂停，书籍页删掉检索与排序、并整体下线基于 foliate-js 的站内阅读器，只保留浏览与下载；网页卡片改成「左缩略图 + 右标题说明」的扁卡片并配编辑 / 置顶 / 删除菜单；游客权限放开：留言与动态的正文对游客开放，普通账号的名字脱敏，评论与回复区整块锁定。

MirrorChyan/user-frontend

参考首页雨滴动画、入口悬停展开和卡片层次表现。

InvenTree

参考元件、项目、附件、库存流水和扩展接口的数据组织方式。

Part-DB

参考项目 BOM、元件资料、事件记录和电子元件管理流程。

BookStack

参考独立附件、下载访问，以及内容与文件分离的设计思路。

Snipe-IT

参考维修记录的日期、状态、费用、处理方和附件字段。

PinMark

书签模块的参考工程：借鉴浏览器书签的目录树、卡片 / 导航视图和书签整理交互。Error酱 在此基础上实现了纯增量导入（Firefox 只补新增网址，不回滚整理结果）、分类拖拽排序和备注标签，具体授权以原仓库说明为准。

firecrawl/anydoc

笔记的 Word / PDF 导入依赖（MIT 许可证，requirements.txt 中的 firecrawl-anydoc）：把 DOC / DOCX / PDF 转成结构化内容，再由 Error酱 渲染成站内 Markdown 并提取内嵌图片。

esptool-js

作为后续浏览器在线烧录 ESP 系列固件的候选参考实现。

Memos

动态（说说 / 日志）参考其卡片式时间线、置顶和标签组织，MIT 许可证；只借鉴交互，代码由本项目自行实现。

Ech0

同类中文动态 / 说说实现参考，AGPL-3.0 许可证；只参考产品形态和交互，未复制其代码。

Artitalk

参考其轻量说说的输入、图片上传与时间线交互，MIT 许可证；未直接引入其代码。

Leaflet

地图渲染引擎，BSD-2-Clause 许可证，以静态文件方式引入本站地图模块。

Leaflet.markercluster

标记聚合插件，MIT 许可证，用于地图上大量标记的聚合显示。

uMap

参考其地图编辑的功能组织：分类着色、弹窗编辑、GeoJSON 导入导出。uMap 使用 AGPL-3.0，本站只参考交互设计，不复制其代码。

Leaflet.Storage

参考其“前端编辑地图要素、通过接口保存”的数据组织思路，WTFPL 许可证。

geo-notes

参考其“标记 + 分类 + 备注”的个人地图交互，MIT 许可证。

Leaflet.ChineseTmsProviders

参考国内瓦片服务在 Leaflet 中的接入方式，本站只内置了高德矢量与卫星两套配置。

Navidrome

参考其自托管音乐库的浏览体验（歌单优先、封面规整），GPL-3.0，仅作交互参考；现在歌曲页只保留歌单列表与「点封面播放 / 暂停」，进度条、随机、循环、音量那一整条播放条已经删掉了。

music-metadata

参考其音频标签与内嵌封面的解析范围（MP3 ID3、FLAC PICTURE、M4A covr 等），MIT 许可证；本站用 Python 标准库实现了对应的解析。

Casbin

参考其「主体 / 对象 / 动作」的权限策略模型和角色继承思路，Apache-2.0 许可证；本站用 SQLite 权限表实现了简化版，没有引入依赖。

sensitive-word

参考其 DFA/Trie 敏感词匹配和全半角、符号干扰归一化思路，Apache-2.0 许可证；本站用 Python 标准库实现了相近的匹配器，词库由管理员自行维护。
